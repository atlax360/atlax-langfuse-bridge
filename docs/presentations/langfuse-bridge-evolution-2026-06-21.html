Contexto

Qué es atlax-langfuse-bridge y por qué importa

Torre de observabilidad FinOps del consumo de Claude Code en Atlax360. Tres piezas coordinadas: hook Stop que agrega usage del JSONL al cerrar sesión, reconciler cron (systemd, cada 15 min) que detecta drift y re-ejecuta el hook, y stack Langfuse v3 self-hosted en GCP PRO. Más LiteLLM gateway, MCP server y browser extension.

El producto real

No es un prototipo — está en producción

El stack Langfuse PRO es auth-gated (no deploy público). Las capturas siguientes son representaciones del sistema interno — hook Stop, reconciler, torre Langfuse v3 y gateway LiteLLM.

hook stop · sincronización

Hook Stop: agrega usage del JSONL al cerrar sesión Claude Code → envía traza a Langfuse. Síncrono, exit 0 siempre, <10s, sin deps de producción.

reconciler · drift cada 15min

Reconciler cron: systemd timer cada 15 min, detecta drift (TURNS/COST/END/MISSING) y re-ejecuta el hook sobre sesiones desincronizadas. Ventana de 24h por defecto.

langfuse v3 · torre de trazas PRO

Langfuse v3 PRO en langfuse.atlax360.ai: Cloud Run (web+worker) + Cloud SQL Postgres + ClickHouse GCE + Memorystore Redis + GCS. Activo desde 2026-05-10.

litellm gateway · virtual keys

LiteLLM gateway en Cloud Run: virtual keys por workload, soft budget, callback langfuse → traza automática de cada llamada al LLM. Vertex AI vía gateway (ADR-016).

Método Centauro

Un ciclo de vida iterativo y completo — no solo código

Un director humano + IA (Opus orquesta, Sonnet implementa). El ciclo es fractal e iterativo: cada feature evoluciona PoC → MVP → MMR y el ciclo entero se repite por sesión (handoff → handoff), versionando de v1.4 a v2.63+.

Roles

  • Humano — director, validador (R12)
  • Opus — orquestador + integración
  • Sonnet — subagentes (<45 min, worktrees aislados)

El /goal iterativo

Condición de cierre numerable (gh / git grep / test:coverage) + límite de turnos → sesiones autónomas de 3–10 h con CI verde como gate.

Versiona desde PoC

Ej.: embeddings PoC v2.0 → MVP v2.5 → MMR; pipeline E2E PoC (fixture) → MVP (flujo real ERIC, 84 nodos). Cada vN tiene milestone medible.

El harness como ventaja competitiva

Autonomía creciente, harness cada vez más robusto

Evolución de la autonomía — subagentes en paralelo (pico)

De brownfield sin CI (22-abr) a v1.0.1 en producción (21-jun) en 16 días activos. La ley incidente → regla → inmunidad funcionó: 14 reglas/ADRs nacidas de fricción real, ningún incidente se repitió. El pico fue 7-may: roadmap de 8 semanas ejecutado íntegro en ~8 horas (20 PRs / 8.8k LOC).

Los 3 niveles de "verde"

nivel-1 subagente → nivel-2 integración → nivel-3 CI (único definitivo).

El harness endurecido

  • 15 invariantes (I-1…I-15) + 20 ADRs + 9 reglas cross-project nacidas de fricción
  • Anti-enroque a 2 intentos · ground-truth vs git
  • Hooks pre-push · cross-validation · smoke E2E · env-parity
  • Cada lección → regla que no se repite

Tres actos, tres meses

  • Acto I · Fundación (22-29 abr · ~37 PRs) — brownfield → 354 tests/89% coverage + LiteLLM M1-M3 + MCP server + browser extension + ADR-001..007 retroactivos. INC-001 (docker down -v) → PreToolUse hook + ADR-008.
  • Acto II · Roadmap a producción (6-11 may · ~64 PRs) — S17-S24 completo en 1 día (7-may); deploy PRO GCP (Cloud Run+Cloud SQL+ClickHouse+Memorystore+GCS); audit 360º (47 hallazgos); upgrade Langfuse 3.173.0; v1.0.1 activo.
  • Acto III · Mantenimiento + gobernanza (19-may → 21-jun · ~7 PRs) — audit bisemanal; intake brownfield cierra gap D7: ADRs 018/019/020, scorecard 81%, Linear 23 issues, 3 PBIs técnicos, corpus 16 retros.

Ley empírica

incidente → regla → inmunidad. INC-001 (docker down -v) → PreToolUse hook + ADR-008. Bug silencioso cost_report ($14.788/sem sin verificar) → smoke baseline obligatorio cross-project. Fix-de-fix ×3 infra GCP (9-may) → gate billing pre-flight + smoke E2E 8/8.

Los dos techos vigentes son humanos

  • Velocidad sin ventana de revisión: 7 fix-of-fix, merges en 5-13s sin revisión humana.
  • Documentación y operación tardías: ADRs post-hoc, checkboxes decorativos, features sin smoke E2E operativo al merge.

Lo que el mercado confirma

La curva que parece exponencial es una escalera de harness, no el modelo.

  • El harness mueve la frontera tanto como el modelo: quitar el andamiaje hunde SWE-bench (80,9 → 45,9).
  • El modelo es intercambiable (Opus 4.7 → 4.8 → Fable 5); el harness es la variable acumulativa.
  • Productividad real ~15-20% neto tras rework; el "90% del código por IA" es hype (real ~50%). La IA amplifica a un equipo fuerte, no lo sustituye.
  • El coste —no la capacidad— es el límite operativo real.

Tesis: el retorno no está en esperar el siguiente modelo, sino en construir mejor harness — la conclusión del mercado, demostrada con datos propios.

El bridge no es solo observabilidad — es la prueba de cómo Atlax 360 puede construir.
